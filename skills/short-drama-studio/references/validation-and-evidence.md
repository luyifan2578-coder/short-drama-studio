# 提示词验证与生成证据

用于批量提示词、资产改名后的复核、跨生成单元接续，以及根据成片问题返修。项目规范决定文件布局、图片后缀、平台时长和字符上限；以下检查只验证这些已确定的口径。

## 1. 当前资产契约

1. 每次开工递归读取正式资产目录，记录相对路径、文件名、扩展名和清单生成时间；同名但不同目录或不同状态图要区分。可给排序后的清单保存哈希，便于识别目录变更。
2. 从项目规范确定提示词应写完整文件名还是省略图片后缀。此口径只作用于正式资产引用；原文对白中的人物称呼、普通物件描述、动态屏显文字不替换成资产名。
3. 审计每份提示词的**全部正文**：总控、逐镜九字段、技术首尾帧、硬约束及连续性附注。若 Markdown 标题或文件名只作剧情索引，按项目规则排除；不要只扫反引号或资产清单。
4. 把所有正式引用与当前磁盘清单逐项精确比较，并另扫未加标记的角色简称、群体代称、旧名、错误后缀和近似道具名。找不到的正式资产列为缺失，说明它是原文需要的普通实体、显示内容还是尚待制作的定稿图；不得虚构文件名或借用不相符资产。
5. 资产文件新增、移动或改名后，先前的“资产检查通过”对受影响提示词失效；重读目录并重跑全文检查。检查记录应注明使用的清单版本，不把旧报告当作当前结论。

## 2. 可复核的文本检查

按项目实际规格给出计数及错误位置，至少包括：

- 原文对白、明确 VO、需准确呈现的文字是否逐项覆盖、顺序正确、说话人与声源一致；动作说明要找到可见动作，不自动归入 VO。若源剧本未标 VO，未加引号叙述只能先称为“旁白候选”，另做适配判断。
- 规格镜头数与标题数、逐镜时长与单元总长、每镜必要字段、技术尾帧是否一致。
- 正式资产名、后缀口径、缺失资产、简称及旧名的全文命中数。
- 人物在场链、门态、道具身份与生命周期、`REAL/DISPLAY/ARCHIVE/AUDIO/VO/POST` 层级是否自洽。结构检查通过后仍需人工核对因果和语义；关键状态不能只凭关键词存在判定通过。
- 平台提示词字符数。若平台上限为 15,000 字符，可把约 12,000 作为工作目标，给平台计数差异和返修留余量；这不是所有项目的固定值。超限先删重复描述，仍超限就在场景、事件或动作边界重拆，再重跑原文、资产、时长与尾帧检查。

记录实际计数和检查范围，避免只写“全部通过”。脚本只能证明文本结构和可识别的名称、数字，不能证明生成画面的角色、口型、道具或连续性正确。

## 3. 从书面尾帧到实际尾帧

- 书面技术尾帧用于计划下一单元；取得成片后，核对实际最后画面、动作收势和完整结束状态。如可用，保存帧图路径及哈希，避免混用旧渲染版本。
- 连续场景按“生成前一单元 → 检查实际尾帧 → 确定下一首态或换场方式 → 提交下一单元”串行推进。保持原定生成单元边界，除非用户要求改变。
- 同场同机位可用平台支持的延长方式；换机位时制作保持人物与道具状态的新首态；明确换场或跳时则重建首态。工具可用性须以当前平台实际功能为准。
- 边界检查只在用户指定范围内进行。用户只要求单元间衔接时，核对相邻实际尾态与首态，不扩展为整条视频的逐镜重审。

## 4. 交付声明

分别记录“提示词文本完成并检查”“平台已受理”“视频已生成”“实际画面已检查”“相邻单元边界已验收”“用户已确认”“剪辑软件已打开并播放验证”。每级附相应文件、任务记录、帧图或可观察操作；前一级不自动推出后一级。

成片返修要保留旧问题的证据、修改范围和新生成版本。修过提示词后，只能声明文本返修完成；同一故障是否消失须由新版画面核对。
