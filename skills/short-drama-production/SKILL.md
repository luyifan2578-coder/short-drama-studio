# 短剧全流程制作｜分镜工作室版

本技能将**项目接收、资产交接、网页执行、结果核验和本地交付**串成一条流程；分镜创作使用同机安装的 [`short-drama-studio`](../short-drama-studio/SKILL.md)。本技能对其方案门禁有一项明确覆盖：分析方案后自主择优并继续执行，不要求逐集弹交互卡或等待例行确认。旧版 `jiuzhou-drama-workflow` 的内置 30S 正文、七字段母版和相应检查脚本不适用于本技能的新稿。单独使用 `short-drama-studio` 时，其原有方案门禁不变。

先按本次请求确定终点。安装、修订或讨论技能，只处理技能；盘点、核对或修改资产清单不授权生图；只做分镜不授权网页提交。完整制作仅在用户对当前项目、范围和生成阶段已有明确授权时推进。项目 `AGENTS.md`、用户已确定的剧本及资产规则优先于通用技能默认值；不把别的项目的造型、模型、费用、授权或暂停状态带进来。

## 阶段选择

| 用户的本次范围 | 执行与停止点 |
|---|---|
| 建档或自动拆集 | 核验来源、保存原稿；按项目要求拆集并逐字回拼，交付分集稿后停止 |
| 全剧资产盘点 | 交付人物、场景、道具三类需求；明确出镜与镜头备选，停止于清单 |
| 已明确授权制作资产 | 核对现有图片并只在授权范围补图；逐张验收，集中交接用户改图 |
| 只做分镜或局部返修 | 按 `short-drama-studio` 完成指定范围，停在经检查的文本和用户指定文件 |
| 完整视频制作或明确断点接续 | 完成获准范围的分镜、网页任务、本地原片和顺序成片；按实际状态交付 |
| 暂停或只查状态 | 不发起新资产或视频任务；核对已受理与未知状态并保存断点 |

## 1. 剧本、项目和资产

读 [来源、拆集与资产交接](references/source-and-assets.md)。读取当前剧本和项目规则；保留来源文件、语言版本、路径及 SHA256。全文分析人物关系、时间线、揭示顺序和空间。独立项目不覆盖同名异稿。自动英文拆集仍以原文字符流不变、每集至少 400 英文词和最多 35 集为默认合同；已有锁定集界或用户指定规则优先。

资产需求按人物、场景、道具三类列清；人物时期与状态放在同一身份下。现有图片须逐张看实际内容、尺寸、名称和指纹；把身份参考、体型或结构参考、正式资产各自的约束范围分开验收，不把参考图误当成成品图。获准制作单人人物资产时，按 [人物资产制作与验收规则](references/source-and-assets.md#人物资产制作与验收) 确定五栏版式、同一造型、空手及独立道具分离；项目另有明确版式时按项目规则执行。只有用户明确要求制作相关资产才生成、提交或下载；图片制作和人工改图交接依项目要求执行。资产清单中的镜头备选不写成剧本事实，也不提前制作。全剧资产交接后若需用户修改，保存断点并等其继续；恢复时复查变更图和依赖，不重复生成已确认素材。

## 2. 分镜创作与直接提交

读 [分镜工作室接入](references/storyboard-integration.md)，再按本次任务读取 `short-drama-studio` 的 `SKILL.md` 和其相关引用页。创作分镜、情绪、表演、机位、技术尾帧、层级标记及文本证据都采用工作室的**当前**规则。每集先完成其方案分析，比较可行边界、时长、场景、情绪和连续性安排，自主选定最符合原文与项目约束的方案，简要记录依据后直接拆镜、出提示词。方案选择不设交互卡或例行确认；只有权威原文冲突、关键输入缺失或涉及尚未授权的生成与费用时，才就具体阻塞点询问。记录实际规则版本与所用文件指纹，不把历史版本号当作当前规则。

已授权的批次可先完成各集方案定稿与正式分镜，再进入视频阶段；同场连续单元的后段书面首态在前段实际成片前仍属暂定。提交后段前，按工作室规则查看前段实际尾态，必要时仅修订受影响的后段首态并重查相邻边界。

**新项目／新集开工门禁：**每集九项方案和连续账本先于任何正式视频提示词；逐生成单元在起稿前运行工作室 [studio_preflight.py](../short-drama-studio/scripts/studio_preflight.py) 的 `seal`，写完运行 `check`，再由执行助手核对原文、同期动作、情绪、人物在场和真实尾态。每份新稿或返修稿在交付或提交前完成一次语义核对；返修重点复核改动处及相邻边界，不逐镜停下请用户确认。保存方案封存、检查结果、正式稿指纹及语义核对记录；缺一项不得将稿件标为 `drafted`／`prepared`，也不得进入网页提交。命名等项目覆盖须先记录来源并做等价全文审计。详见 [分镜工作室接入](references/storyboard-integration.md)。

`short-drama-studio` 生成并核对的正式分镜提示词就是网页提交正文，不另制或另存平台稿。原文对白及已确认 VO／OS 的画面、声音与时间线均留在同一份提示词中；需要后期配音时可另存配画表供后期使用，不为提交平台删改分镜内容或声源指令。提交前核对平台限制；确需调整时只修订这份正式提示词并重查受影响镜头，无法兼容时报告冲突，不暗中生成第二版。网页素材选择器的真实引用节点须逐项绑定并核验；字面 `@` 不等于真实绑定。

分镜提示词提到当前项目已有的角色、道具、场景及实际尾帧等正式资产时，全文各处均严格使用对应资产在磁盘上的完整文件名主体（不包含扩展名）；重复提到仍写准确的文件名主体，不用角色称谓、简称、旧名或泛称代替。选定的实际尾帧须归档为可核查的接续资产，记录源视频任务、取帧时间点、文件路径和指纹；不得用书面预想尾帧为其命名或充数。提交前按当前资产目录审计总控、逐镜、技术首尾帧、硬约束及素材引用，逐字核对去掉扩展名后的名称。原文对白／旁白及需要后期制作的屏显文字不因资产命名而改写；普通动作、空间关系和无正式资产的实体不冒充资产名。用户或项目明确指定另一命名口径时记录覆盖。正文写出名称仍不能替代网页中的真实素材引用节点；节点自动显示的扩展名按平台实际界面核对。

完整制作的正式文件按项目约定保存分镜正文及旁白覆盖表；需要 DOCX 时渲染检查。只做工作室文本任务时遵从其默认对话交付或用户指定路径。项目要求的视觉版式、文件名、语言、女性服装等覆盖技能通用示例。

## 3. 网页生成与结果交付

读 [网页执行与本地交付](references/platform-and-delivery.md)。进入目标平台前核实项目、集号、当前正文与图片版本；模型、画幅、单次时长、素材容量和价格以**当前页面**为准，不能沿用旧项目或默认值。先读取项目指定的视频模式及该模式的真实素材引用方式；没有指定时按当前平台能力和任务要求选择，并记录依据。**项目覆盖：`D:\短剧\八个哥哥` 在剧梦制作或返修分镜视频，只使用“全能参考”模式；不得切换到“首尾帧”“视频编辑”“图片生成”等模式。**每个生成单元在选定模式下实际绑定所需人物／场景／道具，以及连续接续所需的真实尾帧，读回正文和参数后记录一次尝试及价格，只提交一次；受理不明先查历史，不重复点击。

本技能的**实际尾帧**指从当前分镜实际成片末尾选出的、能清楚表现该分镜结束时场景结构与人物空间站位的一帧，用作下一分镜开头的定位依据；并非机械取视频文件最后一帧。应选最终动作收势后、最靠近片段结束且人物位置、朝向及关键道具可辨的有效画面，核对所选画面之后没有改变该状态的动作。若末尾只有切黑、遮挡或不能说明站位的特写，应向前寻找仍代表最终状态的有效帧；若整段末尾没有这样的画面，不把不相符的帧当尾帧通过验收。记录取帧时间点、来源任务与版本。

对连续场，前段成片实际尾态与后段首态构成提交依赖；相邻集数的集尾与集首若属同一连续场景，也按连续分镜处理。新场景、明确跳时等可自包含的单元可按当前授权独立推进。局部质量偏差先定位原片中可保留的画面及剪接点；有该次补制授权后，才为异常镜头及必要的邻近衔接镜头写一段短提示词，在原分镜位置提交一次短时长局部新任务，避免重生多数合格镜头。开头引用紧邻保留片段的**实际尾帧**：异常在中段时用前方保留段的尾帧，异常在开头且无本段保留前缀时用上一个连续分镜的实际尾帧，不误用异常画面、预想尾帧或无关任务尾帧。补段首镜逐项核对角色空间站位、服装、道具和光态；完成后核对异常是否消失、前后拼接点与新尾态。单个分镜的局部补制最多两次，首次与再补制合计；已受理后超时、失败或生成不合格均计入，未受理的输入拦截不计。达到两次仍不合格即停止补制，在最终问题清单列出位置、现象、两次结果与剩余影响，交用户判断；不借换版本重置次数。用户未授权补制时，失败和质量偏差只记录与报告，不自动收费重做。暂停后停止新提交，已受理任务继续核对状态。

使用剧梦制作连续分镜时，前一分镜生成结束后先验收**实际成片尾帧**，记录人物空间站位、场景关系、道具与光态；同一连续场景跨相邻集的集尾与集首也如此验收。下一分镜首镜须继承可核对的空间关系，不得凭空换位或重置场景；人物朝向、手势、表情和机位可随可见动作与剧情自然变化，不要求首帧与前段尾帧画面完全相同，也不得仅因这些变化判定失败。若首态与实际尾态冲突，先修订下一份正式提示词并复核边界，无法自然衔接则暂停后段提交。验收通过后，用剧梦的引用功能把**前一分镜的实际尾帧**作为下一分镜的开头承接状态资产，与本段必需的正式人物、场景、道具资产一起放入选定模式的真实引用节点；本项目统一使用“全能参考”。在下一分镜提示词的承接位置明确写出“承接上一分镜尾帧”（跨集时注明“上一集末分镜”），并在该处插入对应尾帧的真实引用节点。提交前读回正文与全部节点，不能以书面技术尾帧、字面文件名或素材栏缩略图代替实际尾帧引用。记录所引用尾帧的来源任务、取帧时间点及版本；成片后复核相邻镜头的人物空间站位与场景关系。

剧本写“脸色发白／turned pale”等状态时，以笑容收住、呼吸停顿、眼神与唇部的即时反应为主，只允许细微可信的血色变化；保持正式人物资产的原有肤色、妆容、肤质及场景光照，面部与颈部、肩部色调自然相接。提示词与成片均禁止整脸突变惨白或灰白面具、闪白、涂层、换脸、局部曝光突变、发光眼睛等夸张或超自然效果。逐镜检查脸与颈部的色调过渡及相邻镜头一致性；已生成的异常按上述局部补制与正确尾帧引用规则处理，未获该次授权只记录与报告。

区分提示词完成、平台受理、视频完成、实际审片、边界验收、下载、本地合片和用户确认。按当前审查范围查看真实视频与音轨；未审查标记 `not_reviewed`。导出逐集原片，核对文件、时长、尺寸、音轨和指纹，再按序合片；局部补制后另核对平台时间轴与本地接合版是否一致，正式交付指向实际验收的文件。缺段标为不完整。完整视频任务默认终点是获准范围的本地原片及顺序成片，不自行加字幕、后期 VO、音乐、剪映草稿或发布。

## 4. 状态与恢复

读 [状态和证据](references/state-and-resume.md)。来源、资产、正式分镜提示词、网页引用、提交尝试、返回结果和本地文件分别记录版本与证据。计划、脚本检查或平台受理不代表成片合格。正文、图片或规则改变后，只使受影响的未提交核验失效；已受理和已完成结果保留历史。恢复时先读取当前状态与真实文件、网页任务，再决定下一步，避免重复上传、扣费或建项目。
